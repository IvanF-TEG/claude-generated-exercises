## TODO 1: `V1__create_loads.sql`
<details><summary>Hint 1 (syntax)</summary>

`CREATE TABLE loads ( column TYPE constraints, ... );` An auto-generated key is `id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY`.
</details>
<details><summary>Hint 2 (approach)</summary>

One column per entity field, snake_case. `NOT NULL` wherever the entity says `nullable = false`. The `reference` column comes in V3, and `bids` has no column in `loads` (the foreign key lives in `bids`).
</details>
<details><summary>Hint 3 (code)</summary>

```sql
CREATE TABLE loads
(
    id          BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    origin      VARCHAR(255) NOT NULL,
    destination VARCHAR(255) NOT NULL,
    weight_kg   INTEGER      NOT NULL,
    pickup_date DATE         NOT NULL,
    status      VARCHAR(20)  NOT NULL
);
```
</details>

## TODO 2: `V2__create_carriers_and_bids.sql`
<details><summary>Hint 1 (syntax)</summary>

`CONSTRAINT uk_carriers_name UNIQUE (name)`, `CONSTRAINT fk_bids_load FOREIGN KEY (load_id) REFERENCES loads (id)`, `CREATE INDEX idx_bids_load_id ON bids (load_id);`
</details>
<details><summary>Hint 2 (approach)</summary>

Create `carriers` *before* `bids`: a foreign key can only reference a table that already exists. Money is `BIGINT` (a `long` in Java). An `Instant` is `TIMESTAMP(6) WITH TIME ZONE`.
</details>
<details><summary>Hint 3 (code)</summary>

```sql
CREATE TABLE bids
(
    id           BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    load_id      BIGINT                      NOT NULL,
    carrier_id   BIGINT                      NOT NULL,
    amount_pence BIGINT                      NOT NULL,
    status       VARCHAR(20)                 NOT NULL,
    placed_at    TIMESTAMP(6) WITH TIME ZONE NOT NULL,
    CONSTRAINT fk_bids_load FOREIGN KEY (load_id) REFERENCES loads (id),
    CONSTRAINT fk_bids_carrier FOREIGN KEY (carrier_id) REFERENCES carriers (id)
);
```
</details>

## TODO 3: `V3__add_load_reference.sql`
<details><summary>Hint 1 (syntax)</summary>

Four statements: `ALTER TABLE ... ADD COLUMN`, `UPDATE ... SET`, `ALTER TABLE ... ALTER COLUMN ... SET NOT NULL`, `ALTER TABLE ... ADD CONSTRAINT ... UNIQUE (...)`.
</details>
<details><summary>Hint 2 (approach)</summary>

The `UPDATE` has no `WHERE`: every existing row needs a value. `CAST(id AS VARCHAR)` turns the number into text, `LPAD(..., 6, '0')` pads it to 6 characters, and `||` joins strings.
</details>
<details><summary>Hint 3 (code)</summary>

```sql
UPDATE loads SET reference = 'FB-' || LPAD(CAST(id AS VARCHAR), 6, '0');
```
</details>

## TODO 4: the reference in Java
<details><summary>Hint 1 (syntax)</summary>

`@Column(nullable = false, unique = true, updatable = false, length = 20)`. `Optional<Load> findByReference(String reference);`
</details>
<details><summary>Hint 2 (approach)</summary>

`Load`'s constructor already sets a reference for new loads. Add `reference` as the second component of `LoadResponse` and pass `load.getReference()`. The `/by-reference/{reference}` mapping needs a `String` path variable.
</details>
<details><summary>Hint 3 (code)</summary>

```java
public Load getByReference(String reference) {
    return repository.findByReference(reference).orElseThrow(() -> new LoadNotFoundException(reference));
}
```
</details>
