# SB04: A REST API for Loads (CRUD)

**Time box:** 75–90 min · **New concept:** REST resource design, `@RequestMapping` on the class, `@PutMapping`/`@DeleteMapping`, optional query parameters, `201 Created` + `Location`, `204 No Content`, a repository layer, `@WebMvcTest` slices with Mockito `@MockitoBean`

## Learning Objective
Build the core of FreightBoard: an API to **create, read, update, cancel and delete** loads. You'll use the standard three-layer shape (controller → service → repository) that nearly every Spring codebase follows, and test each layer the right way: the repository and service with plain unit tests, the controller in isolation with a mock, and everything together with one integration test.

## Primer: designing a REST resource
A **resource** is a noun with a URL. The collection lives at `/api/loads` and one member at `/api/loads/{id}`:

| Action | Request | Success | Failure |
|---|---|---|---|
| List (with filters) | `GET /api/loads?status=OPEN&origin=LS1` | `200` + JSON array (possibly `[]`) | |
| Read one | `GET /api/loads/7` | `200` + the load | `404` |
| Create | `POST /api/loads` + body | `201 Created` + `Location: http://…/api/loads/7` + the load | |
| Replace | `PUT /api/loads/7` + body | `200` + the load | `404` |
| An action that isn't plain CRUD | `POST /api/loads/7/cancel` | `200` + the load | `404` |
| Delete | `DELETE /api/loads/7` | `204 No Content` (no body) | `404` |

- **Filters are query parameters**, not new URLs: `?status=OPEN`, not `/api/loads/open`.
- **An empty list is not a 404.** "No loads match" is a perfectly good answer: `200 []`.
- **Idempotent** means "doing it twice leaves things the same as doing it once". `GET`, `PUT` and `DELETE` are idempotent; `POST` isn't. The predictions test this.

**The three layers**
| Layer | Annotation | Its job | Knows about HTTP? |
|---|---|---|---|
| Controller | `@RestController` | Turn HTTP into method calls and results into status codes | Yes, and it's the only layer that does |
| Service | `@Service` | Business rules: "a new load is OPEN", "cancelling sets CANCELLED" | No |
| Repository | `@Repository` | Store and fetch data | No |

In Python terms: the controller is your Flask view function, the service is the plain module it calls, and the repository is the data-access code (the SQLAlchemy queries).

**Mocks in one minute.** A mock is a fake object generated by **Mockito**. It returns whatever the test tells it to:
```java
@MockitoBean LoadService loadService;                          // Spring puts the mock in the context instead of the real bean
given(loadService.findById(7)).willReturn(Optional.of(LOAD));  // script its answer
mvc.perform(get("/api/loads/7")).andExpect(status().isOk());   // exercise the controller
verify(loadService).update(7, REQUEST);                        // check the controller called it correctly
```
It's like Python's `unittest.mock.Mock` with `return_value`. Use mocks at the **edges of the unit** you're testing: `LoadControllerTest` mocks the service so it tests *only* the web layer.

| Test | Starts | Speed | Use it for |
|---|---|---|---|
| Plain JUnit (`new LoadService(...)`) | Nothing | ⚡ milliseconds | Logic |
| `@WebMvcTest(LoadController.class)` | Web layer only | Fast | URLs, status codes, JSON shape |
| `@SpringBootTest` | Everything | Slowest | A few "does it all fit together" flows |

## How to Run
From the `spring` folder:
```bash
mvn -q test -pl sb04-rest-crud
mvn -q spring-boot:run -pl sb04-rest-crud
```
Then try the whole lifecycle:
```bash
curl -i -X POST localhost:8080/api/loads -H 'Content-Type: application/json' \
     -d '{"origin":"LS1","destination":"M1","weightKg":1500,"pickupDate":"2031-03-01"}'
curl -s "localhost:8080/api/loads?status=OPEN"
curl -i -X PUT localhost:8080/api/loads/1 -H 'Content-Type: application/json' \
     -d '{"origin":"LS1","destination":"B1","weightKg":1200,"pickupDate":"2031-03-02"}'
curl -s -X POST localhost:8080/api/loads/1/cancel
curl -i -X DELETE localhost:8080/api/loads/1
```
Restart the app and list the loads again. They're gone: memory doesn't survive a restart. SB06 fixes that with a database.

> 💡 **IntelliJ HTTP Client:** create a file `loads.http` and type `POST http://localhost:8080/api/loads`, a `Content-Type` line, a blank line and the JSON body. Click ▶ to send it. It's nicer than `curl` for longer bodies (IntelliJ Ultimate only).
